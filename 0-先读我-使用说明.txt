================================================================================
  TCMS × AI —— 使用说明（新电脑篇）
  先读这个文件。下面三步做完就能用。
================================================================================

这是一个"列车控制软件智能测试平台 + AI 测试工程师 Agent"。
解压后按下面的步骤操作即可，不需要你事先安装 Python。


--------------------------------------------------------------------------------
一、最快路径（三步）
--------------------------------------------------------------------------------

  第 1 步  把压缩包解压到任意目录
           建议路径不要有空格，例如  D:\tcms-agent

  第 2 步  双击   start.bat
           · 第一次运行会自动下载 Python 与依赖，需要联网，约 3~5 分钟
           · 之后每次启动都是秒开
           · 浏览器会自动打开 http://127.0.0.1:8000

  第 3 步  关闭那个黑色命令行窗口即停止服务


--------------------------------------------------------------------------------
二、三个入口（都在根目录）
--------------------------------------------------------------------------------

  start.bat        启动 Web 界面
  agent-demo.bat   让 AI 测试工程师现场跑一遍完整链路（约 1 分钟，全程离线）
  test.bat         自检与测试（环境自检 + 全量回归 + 静态检查 + 评测基线）

  Web 界面左侧有七个页面：
     总览 · 测试资产 · 场景执行 · 故障演示 · 知识图谱 · AI Agent · 设置/引导
  第一次用建议先点「设置 / 引导」，那里有新手引导与资产源说明。


--------------------------------------------------------------------------------
三、这台机器上需要什么
--------------------------------------------------------------------------------

  必需：Windows + 联网（仅首次）
  不需要：Python、Node.js、任何 API key、任何数据库

  为什么不需要 Python：包内自带 uv（一个独立的包管理器），它会自动准备
  Python 3.11 与全部依赖。若你的电脑已装 uv，脚本会直接用它。

  为什么不需要 Node：前端构建产物（web/dist）已随包提供。

  为什么不需要 API key：Agent 默认走"离线规则臂"——它与真模型走
  同一张工作流图、同一套工具、同一套权限与审计，只是决策由确定性规则
  做出。配置 key 后可切换到真模型（见第五节）。


--------------------------------------------------------------------------------
四、常见问题
--------------------------------------------------------------------------------

  Q：双击后窗口一闪而过 / 提示找不到 powershell
  A：本包使用 Windows 自带的 PowerShell。若被安全软件拦截，
     右键 start.bat → 以管理员身份运行；或手动执行：
         powershell -NoProfile -ExecutionPolicy Bypass -File start.ps1

  Q：提示"无法获得 uv"
  A：三种办法任选：
     ① 联网后重新双击（脚本会自动安装 uv）
     ② 手动装：powershell -c "irm https://astral.sh/uv/install.ps1 | iex"
     ③ 从 https://github.com/astral-sh/uv/releases 下载 uv.exe，
        放进本目录的 _offline\ 子目录里

  Q：提示"依赖同步失败"
  A：多为网络或代理问题。若本机配了代理而代理未开，git/uv 会连不上：
         git config --global --unset http.proxy
         git config --global --unset https.proxy
     若拿到的是含离线缓存的完整包（包内有 _offline\uv-cache），
     可设环境变量 TCMS_OFFLINE=1 后重试，全程不联网：
         set TCMS_OFFLINE=1
         start.bat

  Q：8000 端口被占用
  A：换一个端口。注意两条命令要在同一个命令行窗口里依次执行：
         set PORT=8001
         start.bat
     （或直接改 start.ps1 里的默认端口）

  Q：路径有中文或空格，会出问题吗
  A：通常可以，但个别 Python 工具链对含空格路径敏感。
     若遇到莫名报错，换到 D:\tcms-agent 这类简单路径再试。

  Q：想确认"解压出来的这套东西是好的"
  A：双击 test.bat。它会跑：环境自检 → 全量回归 → 静态检查 →
     端到端评测基线（规则臂须达 10/11 且零幻觉引用）。
     全绿即表示本机环境完全正常。

  Q：Web 上点某个功能没反应 / 提示看不懂
  A：先看浏览器开发者工具的 Network 面板。本平台所有接口都在 /api 下，
     未知接口会如实返回 JSON 的 404（不会拿网页顶替），
     所以那里能看到真正的原因。


--------------------------------------------------------------------------------
五、进阶用法（可选，不影响基本使用）
--------------------------------------------------------------------------------

  命令行入口统一用 tcms.bat —— 它会自动找到 uv（PATH 里没有就用包内自带的），
  并自动切换到本目录执行，所以你在哪个目录敲都一样。
  在命令行里运行：

      tcms tools                       列出 15 个工具与四级权限
      tcms run "<目标>"                 跑一个目标（默认离线，不花钱）
      tcms history <id>                回放某次运行的轨迹
                                       <id> 就是 run 输出末尾那行 thread_id
      tcms memory stats                查看四层记忆
      tcms eval run --arms rule        跑端到端评测（只跑离线臂，几秒完成）
      tcms nolib --verify              框架版 vs 手写最小 loop 对照

  提示：直接双击 tcms.bat 可看到全部子命令。

  注意：eval run 不带 --arms 时会连模型臂一起跑——那会真实调用你配置的 API
  （产生费用、约数分钟）。只想验证环境请用上面带 --arms rule 的那条。

  用真模型（需自备 key）：

      set DASH_API_KEY=sk-xxxx
      tcms run "验证车门故障必须触发降级处置" --llm

  开放持久化写入（会要求你在终端逐项审批）：

      tcms run "<目标>" --allow-write

  如果你习惯直接用 uv：上面的 tcms X 等价于在本目录执行 uv run tcms-agent X（需本机已装 uv）。

六、这个包里有什么
--------------------------------------------------------------------------------

  start.bat / start.ps1            启动 Web 界面
  agent-demo.bat / .ps1            Agent 演示
  test.bat / test.ps1              自检与测试
  tcms.bat                         命令行入口（自动找 uv + 切目录，见第五节）
  _tools\common.ps1                启动脚本共用的引导逻辑
  _tools\tcms.ps1                  tcms.bat 的实现
  packages\engine\                 领域引擎与真实资产（原 tcms-can-test）
  packages\platform\               资产模型 + 知识底座 + Web（原 tcms-ai-platform）
  packages\testgen\                受约束生成与变异杀毒（原 tcms-ai-testgen）
  packages\agent\                  Agent：工作流 / 四级权限 / 四层记忆 / 评测
  docs\ARCHITECTURE.md             架构说明（现状，含全部实测数字）
  docs\decisions.md                设计决策记录（ADR：背景 → 决策 → 代价）
  README.md                        项目总览

  详细文档见 README.md 与 docs\ 目录。
  源码与完整 git 历史在 https://github.com/zych2002918/tcms-agent


--------------------------------------------------------------------------------
七、卸载
--------------------------------------------------------------------------------

  直接删除整个目录即可。若还想清掉缓存的 Python 与依赖：

      删除  本目录下的 .venv
      删除  %LOCALAPPDATA%\uv\cache   （这是 uv 的共享缓存，别的项目也在用；
                                        除非确认没有其它项目依赖它，否则不必删）

  以上都不影响系统其它软件。
