# 决策记录（ADR）

> 每条记录：**背景 → 决策 → 理由 → 代价**。目标是让半年后的自己（和面试官）
> 能看懂"为什么当时这么选"，而不是只看到一堆代码。

---

## ADR-001 · 三仓合一为 monorepo

**背景**：`tcms-can-test`（引擎）、`tcms-ai-platform`（平台）、`tcms-ai-testgen`（生成器）
原为三个独立仓库。平台与生成器的 CI 都需要 `actions/checkout` **别的仓库**来当兄弟目录，
源码里也存在大量 `parents[2] / "tcms-can-test"` 这类路径猜测。

**决策**：合并为单仓 `tcms-agent`，各成员置于 `packages/`，用 **uv workspace** 管理，
保留各自完整 git 历史（手动子树法：`merge -s ours` + `read-tree --prefix`）。

**理由**：
1. 跨仓路径假设脆弱且**失效时会静默降级**——迁移后发现 21 个测试因
   `skipif(not UPSTREAM.is_dir())` 全部静默跳过（"测试全绿"但零验证），
   这类问题在单仓里不可能发生；
2. CI 不再需要 checkout 外部仓库；
3. 单 venv、单锁文件，任何 clone 一条 `uv sync` 即可跑。

**代价**：仓库变大（578 文件 / 216 commits）；成员的 .gitignore/CI 需要重新协调
（例如根 `.gitignore` 裸写 `dist/` 会吞掉刻意入库的 `packages/platform/web/dist`）。

## ADR-002 · 编排用 LangGraph，记忆/评测/工具面自研

**背景**：曾考虑纯自研 agent loop（学习最深、零依赖），也考虑纯框架方案。

**决策**：**编排买框架，其余自己造**。

**理由**——LangGraph 内置件几乎逐条命中 harness 的需求，属于"不该自己造的轮子"：

| 需求 | LangGraph 提供 |
|---|---|
| 状态持久化 / 断点续跑 | `checkpointer`（SqliteSaver） |
| 人在环路审批 | `interrupt()` |
| 实时可观测 | `stream()` |
| 轨迹回放调试 | `get_state_history()` time-travel |
| 跨会话长期记忆 | `BaseStore` |
| 工具 schema | OpenAI function-calling 兼容 |

反过来，**框架不解决**的四件事恰恰是 agent 成败的决定因素，必须自研：
1. **工具怎么设计**（描述质量决定调用正确率）；
2. **observation 怎么格式化**（新手最容易翻车处）；
3. **记忆策略与防污染门禁**；
4. **领域评测**（框架不知道什么叫"TCMS 测试任务做对了"）。

**代价**：引入较重依赖（langgraph / langchain-core / langchain-openai，约 20 个包）。
缓解：保留 `nolib/`（M7）——一份手写最小 loop 与框架版跑**同一套评测集**做 A/B，
既作为对照实验，也是"我真的理解循环内部发生了什么"的证据。

## ADR-003 · 工具四级权限 + 双保险门禁

**背景**：TCMS 是安全关键域。让 LLM 直接触发写操作或真实执行是不可接受的。

**决策**：工具按副作用强度分 **R0 只读 / R1 沙箱写 / R2 真执行 / R3 持久化**；
注册表只向模型暴露调用方声明允许的级别，且 `invoke()` 二次校验。

**理由**：
1. 只靠 prompt 提醒"别调用危险工具"不是工程手段；
2. **双保险**：高权限工具既不出现在 schema 里，也不可在 invoke 时执行；
3. 每次执行留审计（名称/参数/级别/耗时/成败/结果指纹），可事后追责。

**代价**：每开放一级权限，必须同时落地对应护栏（沙箱 / 超时 / 审批）。
**只加权限不加护栏是禁止的**——这条纪律写进了 `permissions.py` 的文档。

## ADR-004 · 离线模式是"规则参考实现"，不是假回复

**背景**：项目纪律要求"无 API key 时全流程可跑"。但实现方式有高低之分。

**决策**：无 key 时切换到 `OfflineScriptedModel`——一个**确定性规则参考实现**，
它走同一张图、同一套工具、同一套权限与审计，只是决策由规则做出。

**理由**：
- 做法 A（假回复）：图"跑通"了，但循环、预算、工具回填、轨迹落盘全都没被覆盖，
  测试是假的；
- 做法 B（本决策）：离线运行真实覆盖 harness 基础设施；产出轨迹可作为 LLM 的
  **对照基线**；结果可复现，能进回归门禁。

**代价**：需要维护一份规则实现（约 200 行）。收益是测试可信 + 白拿一个对照臂。
`model_kind` 字段如实区分 `llm` / `offline-rule`。

## ADR-005 · `verify` 作为独立节点：引用强制校验

**背景**：LLM 输出最大的风险是"引用幻觉"——编造一个看起来合理的
`fault:door_fault_super_critical`。

**决策**：图里设独立 `verify` 节点，把结论引用的每个资产 id 回真实图谱核对
（`fault:` → faults.yaml；`req:` → 图谱 requirement 节点；`scenario:` → 场景目录），
产出结构化 verdict。

**理由**：
1. 把"说得像不像"变成"引用真不真"，这是**机器可判**的；
2. verdict 是结构化的，评测体系可直接消费（M6 的"幻觉率"指标就是它）；
3. 独立节点 → 校验逻辑本身可被单独测试与回归。

**代价**：需要维护引用格式约定（`kind:key`），并要求 prompt 遵守。
当前校验只覆盖引用真实性；"结论是否被证据充分支持"仍是人判断的部分（诚实边界）。

## ADR-006 · 记忆长在轨迹上，不另建存储

**背景**：多层记忆（工作/情景/语义/程序性）容易做成"再建一套数据库"。

**决策**：情景记忆**直接使用 LangGraph 的 SQLite checkpoint**（thread_id 即一次
运行的记忆锚点），不新建存储层；语义记忆继续用 platform 的知识底座。

**理由**：轨迹已经是"完整、逐步、可回放"的状态记录，这正是情景记忆的定义。
再建一套只会造成两份真相（trajectory 与 memory 漂移）。

**代价**：checkpoint 表结构由框架管理，检索能力有限（M5 需在其上补"按相似度检索
历史运行"的索引层，而不是改表）。

## ADR-007 · 审批放独立节点，副作用只写在 `interrupt()` 之后

**背景**：要让 Agent 能写长期记忆，同时不能让 LLM 自主决定改系统状态。

**决策**：`approve` 节点是全图**唯一**调用 `interrupt()` 的地方；
执行拆成 `act`（不需审批的工具，无 interrupt）与 `approve`（待审批项）两个节点。

**理由**（这条是实测出来的，不是推测）：LangGraph 在 resume 时会让**被中断的节点
从头重跑**。最小实验结果：
- `interrupt()` 之前的 `prep` 执行了 **2 次**（首次 + 恢复时重跑）；
- `interrupt()` 之后的 `after-resume` 只执行 **1 次**。

所以如果把"执行工具"和"interrupt"放同一个节点且写在前面，**每次审批都会把工具
执行两遍**——对写记忆/提升归档这类副作用是灾难（重复写入、重复计费、审计失真）。
拆节点后：`act` 有副作用但无 interrupt（跑一次），`approve` 的 interrupt 前零副作用。

**代价**：状态里多一个 `pending` 字段，图多一条条件边。换来的是一次审批一次执行。

## ADR-008 · 持久化写入设三道闸，且默认拒绝

**背景**：R3（写长期记忆 / 提升归档）是唯一会改变系统状态的副作用。

**决策**：三道**互相不可替代**的闸门：
1. **权限级别** `max_level`：决定这类工具本次运行**存不存在**（默认只到 R2）；
2. **人工审批**：即便开放，调用也要过人（`approver=None` → **默认拒绝**）；
3. **机器门禁**（工具内部）：即便人批准了，内容仍要过程序校验
   （`write_memory` 的每个引用必须真实存在）。

**理由**：审批是**人的判断**，门禁是**程序的判断**。人可能被漂亮的措辞说服，
程序不会。而长期记忆一旦被幻觉污染，会通过后续检索**自我强化**——比单次回答
出错严重得多。测试里专门验了这条：人批准了但引用是编造的，写入仍被拒绝。

**代价**：写入路径变长（要构造审批载荷、要处理拒绝分支）。
另外拒绝不能是静默失败——它要作为工具结果回填给 Agent，并写进报告
（"被拒：write_memory —— 该写入未发生"），否则"✅ 通过"会误导读者。

## ADR-009 · 对外宣称的词表必须 import，不许手抄

**背景**：R1 沙箱写要把 testgen 的 DSL 词表（kind / setup op / assert op）告诉模型，
否则模型写不出可编译的用例。

**决策**：`dsl_reference` 工具**直接 import** `tcms_ai_testgen.execution` 的
`EXEC_KINDS / SETUP_OPS / ASSERT_OPS`，不在 agent 侧维护任何副本。

**理由**（这是踩过的坑，不是预防性洁癖）：最初我手抄了一份 op 清单，
写完防漂移测试后它**立刻失败**——手抄版漏了 `inject_fault` / `recover_fault`，
且不知道 `expect_encode_error` 同属 setup 与 assert 两个白名单。

手抄的"说明书"危害比没有说明书更大：模型照着它写，却永远编译不过，
而错误信息显示的是"未知原语"——排查方向会被完全带偏。

**代价**：agent 包对 testgen 产生硬依赖（已写进 `pyproject.toml` 与
`[tool.uv.sources]`；此前是未声明的隐式依赖，属于缺陷）。

**推广**：同一条纪律适用于所有"对外承诺的接口/枚举"——**能在运行时读取的，
就不要在文档里复述**。防漂移测试是这条纪律的执行者。

## ADR-010 · 记忆分两条写入路径：日志自动，技能过门禁

**背景**：四层记忆都要落盘，但"自动写"与"审批写"混在一起会让闸门形同虚设。

**决策**：按**是否含判断**把写入分成两条路径：

| 路径 | 内容 | 纪律 |
|---|---|---|
| 运行日志（`journal.py`） | 目标/结果/工具/失败/引用——机器生成的事实 | 自动追加，无需审批 |
| 程序性技能（`consolidate.py`） | 从历史挖出的"经验/规律"——含判断 | **两道门禁**（引用 + 证据） |

**理由**：日志是事实记录，自动写不会污染判断；技能是**结论**，一旦错误入库，
会被后续召回反复强化（自我强化比单次出错严重得多）。所以技能必须：
1. 引用的资产 id 真实存在；
2. 指出它来自哪些运行，且这些 run_id **真的在日志里**。

第 2 条是本项目特有的：**拿不出出处的"经验"不配进长期记忆**。
`consolidate` 默认只出提案、不写盘（`--write` 才落盘），因为"先看清再写"本身就是一道人工闸门。

**代价**：多一层索引与一个巩固命令。收益是长期记忆的**可信度可被机器验证**。

## ADR-011 · 记忆让运行路径依赖，可复现性要重新表述

**背景**：R1 时我写过"离线臂 100% 可复现"的测试。加入记忆后它失败了——
第二次运行召回了第一次的结果，轨迹**本就应当**不同。

**决策**：不为了"测试好看"而在测试里偷偷关掉记忆。改为：
1. 精确表述可复现性：**同一配置 + 同一记忆状态下**可复现；
2. 拆成两条测试：`test_run_is_deterministic_without_memory`（关记忆，轨迹全等）
   与 `test_memory_makes_runs_path_dependent`（开记忆，轨迹必须不同）；
3. 提供 `memory_enabled` 开关，作为 R7「有记忆 vs 无记忆」A/B 的基础。

**理由**：把"测试失败"改造成"更强的两条断言"，而不是把失败的证据藏起来。
路径依赖正是记忆在起作用的证据——它是特性。

**代价**：任何断言"完全确定"的测试都必须显式声明记忆状态，否则含义模糊。

## ADR-012 · 图谱通道只做补充，不做竞争

**背景**：README 曾声称"三通道 RRF 融合"，实际只有两路。要么把宣称改回去，
要么把实现做出来。我选了后者，但过程中发现"做出来"不等于"等权加进去"。

**决策**：图谱通道**只交出文本两路未召回的文档**（纯补充），
并给 `rrf()` 增加 `weights` 参数（默认仍等权，因为等权是没有标定数据时唯一诚实的选择）。

**理由（实测，非推测）**：让图谱与文本两路等权竞争时，本语料下图谱候选
**100% 已被文本两路覆盖**——它不增加召回，只把排序搅乱，golden 从 14/14 掉到 12/14。
一个只稀释不增益的通道没有存在理由。

**发现**：图谱的真实价值点在**症状式查询**（无实体名、文本重合低），
实测 `仪表盘闪烁` 能多召回 3 条（system / function / fault）；而带实体名的查询
文本两路已足够。这个差异是测出来的，不是设计时想到的。

**代价**：语义上"图谱入融合"的强度比"平等第三路"弱。但这个强度是**真实**的——
宁可有一个真实但克制的通道，也不要一个让指标变差的漂亮架构。

## ADR-013 · 重排用可解释特征，不用 LLM

**背景**：融合阶段只用排名，丢掉了"这条为什么被召回"的信息，需要重排。

**决策**：用四个确定性特征（通道共识 / 查询覆盖 / id 字面命中 / 类型先验），
权重显式写在 `FEATURES` 里；不引入 LLM 重排。

**理由**：
1. LLM 重排不可离线复现 → 检索质量进不了回归门禁（而检索是全系统的地基）；
2. 项目已有"LLM 只能在候选内重排、不得引入新文档"的纪律（diagnoser 的仲裁）——
   在检索最底层引入 LLM 只会把不确定性带进地基；
3. 特征权重**可以被评测数据标定**，这比拍脑袋调 prompt 靠谱。

**实测（14 条 golden）**：`min_at` 达标持平 14/14；期望项进 **top-1 由 12/14 升到 14/14**；
被排差的查询 0 条。三条都已写成断言。

**代价**：特征与权重是人工设计的，泛化性弱于学习式重排。缓解办法是 R7 用评测集标定，
而不是现在就换成黑盒。

## ADR-014 · 引用校验必须覆盖"结论正文"，不能只看工具链

**背景**：审计式自查时发现 `verify` 只校验 `state.sources`（工具返回过的 id）。
于是存在一个**半条链路**的漏洞：模型在结论正文里写一个从未被工具返回过的
`fault:xxx`，那条引用根本不进校验链——**幻觉只要不经过工具就查不出来**。

**决策**：用正则从结论正文抽取 `kind:key`，与工具链引用**一起**核对；
verdict 记录每条引用的来源（`from: tool` / `from: answer_text`），失败原因分开表述。

**理由**：一个只覆盖半条链路的校验器，比没有校验器更危险——它制造"已经查过了"的
虚假安全感。这正是本项目反复强调的"诚实边界"要防的东西。

**代价**：正文里的普通冒号文本可能被误判为引用。已加限定：必须匹配已知的
17 种资产前缀 + 合法的 key 形态，并有专门的假阳性测试（`注意：这里没有引用`、
URL、大小写变体都不应被当成引用）。

## ADR-015 · 评测判据不能把"更优行为"算成"更差"

**背景**：R7 首轮评测跑出来，LLM 臂 **8/11 反而不如规则臂 10/11**，失败项恰好是
两条负例（「今天天气不错」「帮我写一首诗」）。

**查证**：LLM 对这两条**礼貌拒绝并给出替代建议、零工具调用**——这是更优行为
（不浪费步数、不硬凑证据）。而我的 `honest_fail` 判据要求 `bool(tools)`
（"证明它真做了工作"），于是把更优行为判成了失败。

**决策**：负例判据改为 `(not passed) and refs_fabricated == 0`，不再要求调用过工具；
同时补一条 `test_always_say_no_agent_cannot_farm_negative_tasks` 防反向刷分
（永远说"不"的 Agent 会在全部正例上挂掉）。

**理由**：**度量把更好的行为算成更差，那是度量的问题，不是被测对象的问题。**
指标是给人做决策用的，判据错了比没有指标更糟——它会引导优化方向反着走。

**代价**：负例判据变宽，理论上更容易被"永远拒绝"的策略刷分。已用上述测试堵住：
负例全过但正例全挂，总分仍然很低。

## ADR-016 · 对照实验要放在**能测出差异**的仪器上

**背景**：首轮评测里 `rule`、`rule-no-memory`、`rule-no-rerank` 三个臂的六项指标
**完全相同**。表面看是"记忆和重排没用"，实际是**仪器不对**。

**查证**：
1. 规则臂的技能是**写死的脚本**——有没有记忆都走同一条路，结构上不可能有差异；
2. 重排影响**检索排序**，而任务是通过 `verify_fault_action`（真执行）达成的，
   排序变化不改变结论。

**决策**：
- 记忆的对照改放到 **LLM 臂**（`llm` vs `llm-no-memory`），并支持**多轮**
  （第一轮结束记忆才有内容，单轮评测必然无差异）；规则臂上的记忆臂直接删掉
  并在代码注释里说明为什么；
- 重排的仪器明确为**检索 golden**（那里实测 top-1 由 12/14 → 14/14），
  并在文档里说明任务级评测测不到它；
- 在 `harness.py::default_arms` 的注释与 ARCHITECTURE 里写明：
  **一个测不出差异的评测，不等于"没有差异"的证据。**

**理由**：把"仪器测不出"当成"效果不存在"，是最容易犯也最难发现的实验错误——
它会让人删掉真正有用的机制。负结果必须连同**仪器局限**一起报告。

**代价**：多轮 LLM 评测成本上升（11 任务 × 2 轮 × 2 臂 ≈ 44 次 LLM 调用）。
因此它不进 CI，只在需要评估时手动跑；进 CI 的是规则臂基线门禁（零成本）。

## ADR-017 · 编排框架买的是能力，不是结果

**背景**：这个项目一开始就面对"自己写的怎么跟成熟框架比"。与其争论，不如做实验。

**做法**：写一份手写最小 loop（`nolib/`，175 有效行），**复用同一批节点、同一个工具
注册表、同一个模型**，只替换编排层；然后在同一套 11 条任务集上跑两版。

**结果（实测）**：
1. **任务结果完全一致**（11/11 逐条相同，`match_rate` 0.9091、平均步数 4.82、
   平均工具调用 3.82 全部相同）→ **框架不参与决策，因此不改变成败**；
2. **编排代码量：框架版更短**（`graph.py` 121 行 vs nolib 175 行）——
   状态合并、条件边、循环都是声明式的；
3. **但框架版另有 210 行 `runner.py`**，换来的是 nolib 完全没有的能力：
   状态落盘、断点续跑、**中断等人**、轨迹回放、流式观测。8 项能力断言可复跑验证。

**决策**：维持"编排买框架、其余自研"。并把这份对照做成可复跑的报告
（`tcms-agent nolib --verify`），而不是写在文档里的一句结论。

**代价**：多维护一份 175 行的对照实现。收益是**这个问题从此有数据可答**，
而且它同时是一份教学材料：读它能看清 reducer、循环控制、终止判定到底在做什么。

**推广**：判断"要不要用框架"的正确问法不是"自研能不能比得上"，
而是**"这项能力值不值得买"**。编排/持久化/中断/回放值得买；
工具设计、记忆策略、评测门禁、领域整合必须自己造——那些是差异点所在。

## ADR-018 · 真语义通道默认关闭，但必须可开、且可度量

**背景**：目标里有"真 embedding"。本机端点实测可用（`text-embedding-v3`，dim=1024）。

**决策**：把向量通道做成**全链可插拔**（知识底座与记忆召回共用同一条解析链），
默认 `HashedEmbedder`（离线、确定性），设 `TCMS_EMBEDDER=api` 时切 `ApiEmbedder`。
**默认关闭**，并把通道名写进轨迹（`· 向量通道 HashedEmbedder`）。

**理由**：
1. 默认开启会让"离线可复现"失效——那是本项目从原三仓继承的第一纪律；
2. 但也不能因此不做：**差异要能被度量**。实测近义查询「车厢门打不开怎么办」：
   字符级通道 0.113（几乎淹没在噪声里）→ 真语义通道 0.515（正确强命中）；
3. 通道名必须进轨迹：不同通道可信度不同，混在一起谈"检索质量"没有意义。

**代价**：多一条依赖外部服务的代码路径。用条件测试覆盖
（`TCMS_EMBEDDER=api` 时才跑语义断言，否则跳过）——**绝不把哈希余弦当语义证据**，
这条纪律原三仓就有明文，这里继续遵守。

## ADR-019 · 运行时要展示真实步骤，不是轮换文案

**背景**：平台一直宣称"过程透明：把 AI 的工作摊开"，但真实使用时发现，
Agent 运行期间界面上只有一句**硬编码的轮换文案**（"正在检索证据…"），
真实轨迹要等跑完才逐条揭示。用户的原话是：**"我需要你不止是提醒当前状态"**——
他要的是白盒，不是进度动画。

**问题定性**：轮换文案不只是"不够好"，它是**另一类不诚实**：
它声称的步骤与实际发生的事没有关系（可能显示"正在评审结果"而实际还在检索，
也可能显示了永远不会发生的步骤）。在一个以"机器自证、可审计"为卖点的项目里，
用一个假进度展示"透明"，是自相矛盾的。

**决策**：
1. 后端每条轨迹附带**结构化载荷**——真实查询串、完整候选集与选择理由、
   该场景**实际注入了哪些故障**、断言 expect→actual 逐条明细；
2. 提供 SSE 流式端点 `/api/agent/run/stream`，**每产生一条真实轨迹就推一条**；
3. 流末尾给出与 `POST /api/agent/run` **同构**的完整报告，
   避免前端为了拿结果把任务再跑一遍（那会多花一次真执行 + 一次模型调用）；
4. 前端把"思考中…"整块换成 `LiveWhiteBox`：真实步骤逐条出现，每步可展开核对载荷；
5. 对于**不开流**的路径（自由目标 / 组合 / 诊断走普通 POST），
   如实显示"请求处理中…（这条路径不提供逐步轨迹）"——
   而不是借用白盒的措辞（那会变成新的假状态）。

**代价**：多一个端点、多一层线程与队列、前端多一个组件。
另有两条必须守住的实现细节：推送回调**抛异常不能影响正跑的任务**
（已用测试固定）；流不可用时要显式告知，不能静默退回假进度。

**顺带发现**：轨迹原来只有一句话，白盒根本做不起来——所以这次不只是加了个视图，
而是把 `TaskRun.log()` 从"记一句话"升级为"记一句话 + 一份可核对的结构化事实"。
白盒的料在前端之前就已经决定成败了。

## ADR-020 · "注入次数"与"故障个数"必须分开说

**背景**：用户从"车门传感器偶发噪声"点进动画，看到注入了三个故障，问：
"是偶发噪声需要这些前置故障，还是多余注入？"

**查证结果**：两者都不是。`scenarios/soc_temp_door_noise.yaml` 本身就是
一个三故障并列场景（SOC 偏低 + 电池温度偏高 + 车门噪声），
**步骤之间没有前置依赖**——场景 YAML 是 `inject/recover + at` 的扁平序列，
数据模型里没有任何表达"故障 A 需要故障 B 先发生"的字段。

**决策**：把这个回答做成**对所有场景通用**的机制，而不是给那一个场景打补丁
（全库 104 个场景里 **61 个**是多故障，最多 6 个）：
新增 `core/scenario_view.py` 摊开场景构成，新增端点
`GET /api/scenarios/{file}/composition`，前端在多故障场景顶部显示解释卡，
并给出一句**可直接照读的演示口径**，免得演示现场被问住。

**被测试逼出来的修正**：第一版把"注入了几次"当成"有几个故障"，全库不变式测试
立刻抓出反例——`overspeed_reinject_repeat.yaml` 注入了 **2 次**但只涉及
**1 个**故障（超速恢复后重发）。若不区分，解释会在所有重发型场景上说错话。
因此现在两个数分开给出（`total_injections` / `total_faults`），
措辞也分三种：单次注入 / 恢复后重发 / 多故障并列。

**代价**：多一个模块、一个端点、一个前端组件，以及一条**全库不变式测试**
（断言每个场景的构成统计与 YAML 步数逐项一致——这条正是抓出上述缺陷的那条）。

## ADR-021 · 合并仓库会改变"写文件"的含义

**背景**：三仓合一后，跑完 Agent（或评测）会在仓库里留下一个未跟踪文件：

```
packages/engine/tests/test_ai_generated_p2.py
```

**根因**：`executor_real` 按设计把编译出的 pytest 文件写进 ``<upstream>/tests/``
（那样才能看到引擎的 conftest 夹具），而 agent 的 `_exec_worker` 为了回传
`report_path` 传了 `keep_artifacts=True`。

在旧的"双仓平级 clone"布局里，upstream 是**另一个仓库**，写在那里无所谓。
**三仓合一后 upstream 就是本仓的 `packages/engine`** —— 同一行代码的含义变了。

这条值得单独记，因为它不是"某个函数写错了"，而是**重构改变了既有代码的语义**：
没有一行代码被修改，但"往 upstream 写文件"从"写到邻居仓库"变成了"写到自己家"。
合并仓库时，这类"路径指向的对象变了"的地方要专门过一遍。

**为什么原有测试没抓到**：`test_drafts_never_touch_the_repo` 已经存在，
但它只覆盖 `draft_test_case`（R1 写入），**没有覆盖 `run_draft`（R2 执行）**——
而污染正好发生在没覆盖的那一半。一条测试覆盖了承诺的一半，比没有测试更危险：
它给出"这条承诺有人守着"的错觉。

**决策**：执行器跑完**立刻把生成物搬出上游树**（落点由 `TCMS_AGENT_ARTIFACT_DIR`
指定，agent 传沙箱的 `drafts/generated/`）；未指定落点则直接删除。
载荷里不再回传上游树内的路径——那会诱使上层去归档一个已不存在的位置。

**测试**：新增 `test_run_draft_does_not_pollute_upstream_tree`，**两侧都断言**：
① 上游源码树干净；② 产物确实留在沙箱里。
只断言前者会纵容"顺手把产物删掉"的修法——那等于把审计能力也一起删了。
另加 `.gitignore` 安全网（`test_ai_generated*.py`），防进程被强杀在搬走之前。

**代价**：产物路径变了（从上游 `tests/` 变为沙箱 `generated/`），
任何依赖旧路径的外部脚本都需要跟着改。目前仓内无此依赖（已全库检索确认）。

## ADR-022 · 界面上广告的示例，必须真的能用

**背景**：用户在 Agent 输入框里打了「不能发车」，得到的是
「未在目标里识别出任何故障（可用的 203 个真实故障均未命中）」。
而这句**正是界面提示里给的例子**（"期望（如：不能发车 / 降级 / 停车）"）。
用户的疑问一针见血：**这明明是提示词中的一个，为什么搜不到？**

顺着查下去发现三层问题，一层比一层深。

### 一、「不能发车」不是故障名，是现象

它不在任何故障的 name 里，但在 **6 条故障的 desc 里**——词典恰恰是用现象写的：
`door_fault.desc = 「车门状态不可信，禁止发车」`。数据是关联的，
只是匹配方向反了（原逻辑要求"故障文本 ⊂ 用户目标"）。

**决策**：加"现象反查"（`find_situations` / `faults_for_situation`），
用户只说了现象时，反查出哪些真实故障会表达它，交给用户点选。

**两条纪律**：① **现象不映射到 action**——这 6 条里 5 条 derate、1 条 warning，
硬映射成某一个就是编造；② **数字如实**——展示 5 条而实际 6 条时要说
"共 6 条（这里显示前 5 条）"，不把切片长度当总数。

### 二、还有两个广告过的示例是坏的

把前端与文档里所有广告过的句子拿去实测：

```
验证紧急制动失败必须停车    （AgentPage 占位符）  -> 未锚定  ✗
紧急制动失败会怎样        （GraphWorkspace 占位符）-> 未锚定  ✗
```

原因是 bigram 兜底**把参数传反了**（注释写的是"名称的 bigram 覆盖"，
代码算的是"目标有多少落在名称里"），长句一稀释就掉到阈值外。
广告的例子与实现之间隔着一条没人走过的路——**因为没人测过**。

**决策**：把这批句子固化成测试 `ADVERTISED_GOAL_EXAMPLES`，
并与前端逐个对齐；新增示例必须同步加进去。

### 三、修方向之后，必须重新标定——而我第一次放松过头了

- **阈值 0.5**（原 0.6）：16 条无关样本对全部 203 条故障的最大覆盖率 **0.33**，
  应命中的最低 **0.57** —— 0.5 落在中间；
- **近似命中权重 1.5**（原 2.5，精确是 3.0）：近似若也拿 2.5，
  「精确 3.0 vs 近似 2.5」差距仅 0.5，会掉出「明确命中」要求的 1.0 分差，
  把确定的结果降级成歧义（door_fault 与 rear_door_fault 撞车，0.95→0.85）；
- **首尾锚定**（`_both_ends_in`）：只看覆盖率会把长句里**碰巧重合的前缀**也算命中——
  目标「开门到位灯闪，门状态可能不可信」（症状式描述）对故障「开门到位超时」
  覆盖率 **0.60**，比应当命中的「紧急制动失败」的 0.57 **还高**，纯阈值分不开。
  差别在尾部：目标有「开门到位」却没有「超时」。
  要求首尾都在，就把"中间插词"（真该容忍）与"只重合一半"（假阳性）分开了。

**这次过度放松是被自己的评测门禁抓住的**：它让 `T-DIAGNOSE-LAMP` 不再走症状
诊断路径，基线从 10/11 掉到 9/11，`test_baseline_task_set_gate` 变红。
门禁按设计工作了一次——这是本项目第一次"自己建的仪器抓住了自己犯的错"。

### 四、顺带修掉一句自相矛盾的提示

无候选时 `followup_question` 仍在说「**上面**哪个最接近你想验证的？」——
"上面"什么都没有。**指向空气的提示比不给提示更糟**，因为用户会去找不存在的列表。

**代价**：`parse_free_goal` 是 agent 与 platform 共用的解析器
（`nodes.py` 直接 import 它），所以这里的任何放宽都会同时改变
智能体的任务解析行为。这次正是因此才被评测门禁发现——
**共用解析器意味着"改一处、动全身"，标定必须跑全量而不是只看单个函数。**
