# 置信度口径约定（P2-2）：`confidence` 是排序分，不是概率

适用范围：`/api/agent/diagnose` 的候选 `confidence`（及诊断步骤 plan 中的同名域），
由 `agent/diagnoser.py::_CONF` 表确定性计算。

## 语义（一句话）
> `confidence` = **该候选在证据链中的"依据充分性"排序分数**，仅由
> `(因果跳数, 依据类型)` 单调决定；它不是、也不应被当作真实概率。

## 规则
- 取值表（锁值测试防漂移）：
  | (跳数, 依据) | 排序分 |
  |---|---|
  | (1, real_mechanism) | 0.85 |
  | (2, real_mechanism) | 0.70 |
  | (3, real_mechanism) | 0.60 |
  | (1, derived)       | 0.50 |
  | (2, derived)       | 0.40 |
  | (3, derived)       | 0.35 |
  | 越界 key           | 0.30（回落默认）|
- 单调性：真实机制 > 同跳 derived；跳数越深排序分越低。
- 任何 UI/文案/回复 **不得**以“85% 概率/八成把握”等口吻表达（“置信度 X%”标签
  已改为“依据分/排序分”并带非概率说明）。该分数只用于**同批候选内排序**与
  可分性判断（P1-2 澄清阈值 gap <0.15）。

## 为什么不是概率
概率需要真实执行/复现的统计口径；当前 54 条因果边是资产派生的确定性知识，
不是观测频率。若未来用真实 run 记录做校准（P2-3/P2-2 校准分析），须另出字段
并明确其统计语义，不得复写本口径。

## 门禁
- `tests/test_diagnose_sessions.py::test_confidence_table_locked_as_ranking_score`
  锁值与单调性；改表即失败。
- UI 源码不应再出现把诊断排序分读作百分比概率的文案（本约定落地时已清理）。
