# TCMS × AI 前端重构 — 设计计划（依 frontend-design skill）

## 1. 设计简报（subject matter grounding）

- **产品**：列车控制软件测试平台（TCMS × AI）——工程师查看列车报文/故障/安全需求，跑场景，问知识图谱，指挥 AI Agent。
- **受众**：轨道交通测试工程师 + AI 好奇的小白（演示对象）。
- **主任务**：让用户 30 秒内明白"我能看什么、跑什么、问什么"，且每个动作有真实结果。
- **视觉语言来源（行业）**：轨道信号灯（红/黄/绿不是装饰而是状态语义）、运行图（时间×事件的时间线）、驾驶台（密度高但分区清晰）。**用信号色表达测试状态是"结构即信息"，不是装饰。**

## 2. 设计计划 vs AI 默认（自我批判）

| 轴 | 常见 AI 默认（要避免） | 本项目选择 |
|---|---|---|
| 背景 | 暖米白 #F4F1EA + 陶土橙；或近黑 + 单一酸性绿 | **深蓝黑"驾驶台夜视"** `#0A0F1E` + 冷钢蓝 `#1E2A44` 面板，避免纯黑 #0B0B0B |
| 强调色 | 单点 acid 绿 | **信号三色作语义**：绿=通过/PASS、黄=降级/warn、红=故障/FAIL，蓝=信息/操作 |
| 卡片 | SaaS 同款圆角+同灰阴影 | 面板用**细边框 + 极轻区分**，圆角分层（面板 10、控件 6、标签 pill 999） |
| 字体标签 | ALL-CAPS eyebrow + 'A · B · C' + spaced em dash | 中文为主，**sentence case 标签**，少用眉题；技术标识（hex/报文名）用等宽但克制 |
| 动效 | fade-slide-up 每节 + 卡片 hover | 仅"动作反馈"：执行中步骤逐条点亮、检索后结果出现，一次编排 |

## 5. 信息架构（用户视角命名 + 无功能即删）

**发现的问题（来自当面试用）**：
- 总览页 = 纯数字陈列，无动作 → 改造成**真正的仪表盘**：顶部一句话系统状态（上游就绪/资产数/最近一次 run 结果），下方"从这里开始"三张行动卡（跑场景 / 问图谱 / 指挥 Agent），删掉无意义的重复计数卡。
- 每页顶部重复的"TCMS × AI 测试平台"横幅占空间 → 移除，页名进 topbar。
- Agent 页"全部执行"与"执行任务"并存 → 明确主按钮=执行当前任务，次级=全部。
- 报文列表行点击无主功能 → 改为明确行内"查看详情"与"在图谱定位"双动作。

## 6. 原则

1. 状态用信号色表达，颜色必须有意义（非装饰）。
2. 一个页面一个主角动作；其余安静。
3. 每个数字/标签可溯源（继承"机器自证"——悬停显示来源）。
4. 窗口从 1280 到 1920+ 不错位：栅格 auto-fill + 表格横向滚动容器 + 侧栏折叠。

## 7. 落地后的偏离记录（**以代码为准**）

§3 / §4 是**当初的计划**；与 `web/src/index.css` 冲突时一律以代码为准。本节记录计划 → 实现之间
真实发生的偏离，以及偏离的理由。

### 7.1 色板：蓝调"驾驶台夜视" → 中性灰阶

计划选的是蓝调底（`#070B16` / `#1E2A44`），实现最终落在**不带色相的中性灰阶**：

| 层 | 暗色 | 亮色 | 说明 |
|---|---|---|---|
| 底 | `--bg: #08090a` | `#f7f8f9` | 不带色相，避开"一眼 SaaS 模板"的蓝 |
| 面板 | `--surface: #0e0f11` | `#ffffff` | 靠 `--line: #26292d / #e4e6ea` 细边框分层，不用阴影堆叠 |
| 抬升 | `--surface-2: #151719` | `#f4f5f7` | 表头、分段控件的底槽 |
| 文字 | `--ink: #f2f3f5` / `--ink-dim: #9ba1a9` / `--ink-faint: #6c737c` | `#0f1115` / `#5b6472` / `#8b93a1` | 三级足够，不再多造 |

**为什么改**：蓝底色相会和信号三色抢注意力——**语义色只有在无彩色底上才读得出"这是状态"**。
中性底还让 DBC 报文名、图谱连线这些"本来就带色"的内容，成为画面里唯一的彩色来源。

**例外（有意为之，不算漂移）**：FaultLab 的列车示意图与速度曲线（`FaultLabPage.tsx` 内的两段内联 SVG）
固定使用深底 + 亮线的**仪表盘配色**，不随主题切换，因此那两段里保留了硬编码色值。
理由：它们是"夜视仪表"插图，亮色主题下作为深色内嵌块反而更有信息层级；若改成跟随主题，
红/黄告警在浅底上会失去发光感。**口径：除这两段 SVG 外，其余位置不得出现硬编码色值**，
一律走 `index.css` 的语义 token。

### 7.2 语义色只表示状态，不做装饰

`--ok #3ecf8e` / `--warn #f5b544` / `--bad #f87171` / `--info #8b93ff` / `--vio #b39dff`（暗色），
亮色为 `#0d9f6e / #c2740a / #dc2626 / #4f46e5 / #7c3aed`。

落地口径：像"推荐从这里开始"这种**强调**用 `tone="dim"`，不用 info 蓝 —— 否则用户分不清
"这是操作建议"和"这是状态告警"。一处误用就足以让整套颜色语义失效。

### 7.3 图标：Unicode 字符 → 内联 SVG

计划里没有图标策略，实现中一度全站用 `▶ ⚙ ◈ ✦ ◎ ◌` 等字符当图标。问题不是"不好看"，而是**不受控**：
字形由系统字体决定（Windows / macOS / Linux 渲出三种粗细与基线），可能落进 emoji 字体渲成彩色，
且这些字符来自不同 Unicode 区块，线宽天然不一致——放同一行就显得"拼凑"。

现统一到 `web/src/components/icons.tsx`（零依赖；16 视框 / 1.5 线宽 / `currentColor` / `aria-hidden`）。
判定规则写在模块头注释，一句话：**自己独占一个"图形位"→ 用 SVG；旁边有词 → 它是排版标点。**
因此 `→ ✓ ✗ △` 留在正文里，而 `▶ ⚙ ✕ ⤢ ●` 这类槽位字形全部替换。

### 7.4 互斥切换用真 Tab 语义

"2D / 3D"这类分段控件用 `role="tablist"` + `role="tab"`（见 `components/ui.tsx` 的 `Tabs`），
而不是两个并列按钮——并列按钮**让人分不清哪个是当前状态**。

副作用（踩过一次，记下来）：任何按 `role="button"` 定位它的自动化都会静默失效。
`e2e/main-flow.mjs` 已改为按 `role="tab"` 与**可访问名**断言，不再依赖字形文本——
图标换了、文案带不带字形，都不会再让验收脚本假失败。
