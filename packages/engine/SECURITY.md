# 安全策略（Security Policy）

TCMS-CAN-Test 是教学/演示级列车控制与管理系统（TCMS）CAN 总线仿真与安全逻辑
验证项目。虽然本项目模拟的是安全关键系统的测试面，但**它本身不是经过认证的
车载安全软件**——请勿直接用于真实列车控制系统。

## 支持的版本

只有**最新发布版本**（GitHub Releases）接收安全修复。旧版本不保证修复。

| 版本 | 支持状态 |
|---|---|
| 最新 Release | ✅ 积极修复 |
| 更早 Release | ❌ 不接收修复，请升级 |

## 报告漏洞（Reporting a Vulnerability）

如果发现安全相关缺陷（例如：联锁逻辑绕过、超速判定被规避、事件记录器数据
完整性破坏、CRC 校验绕过等），**请勿公开提交 Issue**（避免 0-day 泄露）。

请通过以下方式私密报告：

1. 在 GitHub 仓库创建 **Security Advisory**（仓库主页 → Security → Report a vulnerability）
2. 或直接邮件联系维护者：**1612836914@qq.com**

我们承诺：

- **48 小时内**回复确认收到报告
- **7 天内**给出修复计划与时间表
- 修复发布后，在 CHANGELOG 与 Release Notes 中致谢报告者（如同意署名）

## 已知安全设计（Security Design Notes）

本项目模拟了真实列控系统的安全内核，以下设计请勿在集成时弱化：

- **EBM 故障安全**：SIL4 类原因任一触发即制动（宁可错杀）；缓解必须满足
  零速 + 有效速度信号 + 原因全部消失
- **超速防护**：EBI 阈值不可被任何运行模式覆盖（对齐 EBM 的 CRITICAL 处置）
- **看门狗监督**：节点心跳丢失超过阈值即判离线/故障，恢复需连续有效心跳
- **事件记录器**：紧急制动/错误状态事件为保护类型，环形缓冲不被普通事件驱逐，
  支持事故冻结窗口导出
- **CRC-8 校验**：关键报文携带 CRC，位翻转/字节损坏可被检测

## 依赖安全

项目依赖（见 `requirements.txt`）通过 CI 每日/每次提交执行：

- 单元测试（3 个 Python 版本矩阵）
- 覆盖率门禁 `--cov-fail-under=97`
- 静态检查（ruff lint + format check）

请定期 `pip-audit` 或依赖扫描（如 GitHub Dependabot）检查依赖漏洞。
