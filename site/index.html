TCMS × AI —— 列车控制软件测试平台与 AI 测试工程师 Agent

列车网络控制系统（TCMS）跑在 CAN 总线上，这套平台用来测它。用例、故障字典、场景都是真资产， 逐条登记在 docs/claims.toml 里对实物核验（下面那几个数字就是从那儿来的）。 还有一层 AI Agent：查知识库、造用例、在本机真跑，结论带出处，能顺着点回去核对。 全部离线可跑，不需要任何 API key。

它做什么

  • 测 CAN 报文：周期、ID 合法性、信号值域、边界、枚举、事件联动、丢包检测、安全联锁、紧急制动。
  • 知识底座：知识图谱 + 混合检索（BM25 + 向量 + RRF 融合），故障字典与安全需求都在里面。
  • 受约束生成：DSL 编译成真 pytest，变异杀毒与反思自愈，生成的用例要能杀掉变异才算数。
  • Agent 层：四级工具权限（只读 / 沙箱写 / 真实执行 / 持久化）、人在环路审批、引用强制校验。

跑起来

前置只有两样：Python 3.11+ 和 uv。

git clone https://github.com/zych2002918/tcms-agent.git
cd tcms-agent
uv sync
uv run tcms-agent demo        # 离线跑一遍，不需要任何 key

平台界面：uv run tcms-platform serve，然后打开 http://127.0.0.1:8000。

没有在线演示，这是故意的。它是个要跑 Python 的本地工具，测的是一条虚拟 CAN 总线， 塞进浏览器里只能做成假界面。想试就 clone 下来，上面两条命令能跑起来；本机跑不动再提 issue。

数字怎么来的

文档里的每个数字都登记在 docs/claims.toml，由 scripts/check_claims.py 逐条对着实物核验，对不上 CI 就红。拿不到数据的项如实跳过，仓外的口径卡如实标「外部」， 两者不混。本页的数字与 README 同源，同样受这套门禁约束。
