TCMS × AI

列车网络控制系统（TCMS）跑在 CAN 总线上，这套平台用来测它：报文周期、ID 合法性、信号值域、 事件联动、丢包检测、安全联锁。引擎里是 960 条真用例、203 条 FMEA 故障、104 个可执行场景， 不是演示数据。上面又加了一层 AI 测试 Agent：查知识库、造用例、在本机真跑，结论带引用。

先说清一句容易误会的话：Agent 默认走离线规则臂，不吃 key。决策靠规则， 结论由引擎断言和引用校验兜住。想让它用真模型选场景、给理由，加 --llm 并配 key； 没配就如实降级成规则臂，并在界面上标明这次是谁在决策。

跑起来

前置只有 Python 3.11+ 和 uv。装依赖、起界面都在本机，没有云端环节。Windows 上也可以直接双击 start.bat（起界面）或 agent-demo.bat（跑一遍完整链路）。

git clone https://github.com/zych2002918/tcms-agent.git
cd tcms-agent
uv sync
uv run tcms-agent run "验证车门故障必须触发降级处置"   # 离线跑一个目标
uv run tcms-platform                                  # 起 Web 界面，自动开浏览器

做不到和没做的

  • 没有在线演示。它要跑 Python，测的是一条虚拟 CAN 总线。做成网页版只能是假界面，不如不做。
  • 全仓有 4 条用例是条件性的：真语义向量通道 2 条、真实 CAN 硬件 1 条、平台语义通道 1 条。没条件就 skip，skip 不算通过。
  • LLM 臂要自己的 key。仓库里没有内置 key，也不打算有。
  • 平台前端是给本机看的，没做多用户、权限和部署方案。

数字怎么保证是真的

本页与 README 里的数字登记在 docs/claims.toml，由 scripts/check_claims.py 对着实物逐条核验，对不上 CI 就红。拿不到数据的项如实标"跳过"，仓外的口径卡如实标"外部"，两者不混。
